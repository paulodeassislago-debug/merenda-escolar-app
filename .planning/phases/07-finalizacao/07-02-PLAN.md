## ASVS L1 Threat Model

| Boundary | Description |
|---|---|
| operator/browser → local development services | Manual UAT crosses the browser into Vite, FastAPI and mutable SQLite state. |
| controlled meal request → inventory/audit persistence | Untrusted or invalid meal inputs cross the backend transaction boundary. |
| repository evidence → future release decision | UAT text can be incomplete or misleading if statuses and provenance are not recorded. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-07-02-01 | Information Disclosure | `07-UAT.md` controlled-data evidence | high | mitigate | Prohibit credentials, JWTs and secrets in artifacts; record only non-sensitive identifiers, balances, factors and audit fields. |
| T-07-02-02 | Tampering / Repudiation | UAT status and evidence rows | high | mitigate | Require expected/result/status/source for F1-F17, preserve historical provenance, and block approval for missing or failed evidence. |
| T-07-02-03 | Tampering / Denial of Service | `POST /refeicoes` stock and audit transaction | high | mitigate | Run targeted and full pytest suites plus controlled missing-conversion and insufficient-stock attempts, verifying unchanged balance and audit history after each failure. |
| T-07-02-04 | Spoofing / Access Control | reconstructed F1-F5 flows | high | mitigate | Fresh browser checks cover profile redirects, unauthenticated protection, wrong-profile redirect and removal of both persisted auth keys. |
| T-07-02-05 | Availability | mutable SQLite UAT setup | medium | mitigate | Back up `backend/merenda.db`, use unique UAT records, document reset/recreation, and block the run if the documented development credentials or browser environment are unavailable. |
</threat_model>
