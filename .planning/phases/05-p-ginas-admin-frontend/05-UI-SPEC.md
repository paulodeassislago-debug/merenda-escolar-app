# Phase 5 — UI Design Contract

> Visual and interaction contract for the 7 admin pages (Dashboard, Usuários, Itens, Cardápio, Receitas, Planejamento, Entregas). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Authoritative sources (locked, do not re-litigate):** `.planning/PROJECT.md` (brand rules from the school crest), `05-CONTEXT.md` D-01…D-13, `05-RESEARCH.md` (API + modal/CSS patterns). Tokens below reference the **exact** CSS variable names already defined in `frontend/src/index.css` `:root`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — plain co-located CSS per page (locked by CONTEXT.md **D-01**; shadcn initialization declined by that locked decision, not re-asked) |
| Preset | not applicable |
| Component library | none — hand-rolled per page, replicating structure from `Login.tsx`, `CardapioPublico.css`, `PainelCozinha.css` (modal), `DashboardGestao.tsx` (loading/error/empty) |
| Icon library | none — text labels only. .planning/PROJECT.md §7 forbids emojis as functional icons and icons outside the palette (legacy `📊` in `DashboardGestao.tsx` is an anti-pattern, do **not** replicate) |
| Font | `--fonte-sans` (system-ui, -apple-system, 'Segoe UI', sans-serif) on **all** admin screens. `--fonte-serif` is **proibida** nas telas operacionais (.planning/PROJECT.md §3) — serif only exists in Login/Cardápio Público |

**CSS architecture (D-01):** one `.css` file co-located per page (`Dashboard.css` beside `Dashboard.tsx`, etc.), classes sem framework de utilitários, colors **only** via `var(--*)` tokens from `index.css`. No new global stylesheet; the shared look comes from tokens, matching the existing `Login.css`/`CardapioPublico.css` convention. Tailwind stays inactive.

**Anti-patterns (never ship in this phase):** hex colors outside the palette (`#2563eb`, `#16a34a`, `#f8fafc`…), black modal overlay (`rgba(0,0,0,…)`), inline `style={{}}`, `alert()`, emojis, dark surfaces, hardcoded API URLs.

## Spacing Scale

Declared values (multiples of 4; implemented as rem — `1rem = 16px` — matching existing files):

| Token | Value | rem | Usage |
|-------|-------|-----|-------|
| xs | 4px | 0.25 | Badge/micro inner gaps, tight inline gaps |
| sm | 8px | 0.5 | Label→input gap (`.form-group` margin), gap between action buttons in a row, sidebar nav gap |
| md2 | 12px | 0.75 | Input/button vertical padding (existing `.form-input` uses `0.75rem`), table cell vertical padding |
| md | 16px | 1 | Default element spacing: card grid gaps, form field gaps, modal section gaps |
| lg | 24px | 1.5 | Card padding (.planning/PROJECT.md: 16–24px — use 24 for page-section cards), `.layout-conteudo` page padding (already set by Layout), header→content gap |
| xl | 32px | 2 | Between major page sections (page header ↔ table card ↔ secondary card) |
| 2xl | 48px | 3 | Major breaks only (e.g., dashboard hero row ↔ detail sections) |

Exceptions:
- **Border radius** `--raio` = 8px; modal/large-card radius = 12px (form tokens, not spacing).
- **Badge pill padding** `3px 9px` exists in `Layout.css` (legacy Phase 4, sidebar only) — do not retrofit; **new** badges in admin pages use `4px 8px` (xs + sm) with `border-radius: 999px`.
- Touch targets: desktop-first app; interactive controls (buttons, selects, row actions) minimum height **40px** (derived from input padding 12px + 16px line), not 44px — admin desktop use per phase scope.
- `3xl (64px)` not used in this phase.

## Typography

All admin screens: `--fonte-sans` only. Exactly 4 sizes, 2 working weights (+1 restricted emphasis weight — see rule below).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (1rem) | 400 | 1.5 | Form inputs, modal body text, page intro text, dropdown options |
| Dense/secondary | 14px (0.875rem) | 400 | 1.5 | Table cell text, helper text, empty/error state body, metadata (datas, IDs) |
| Label/micro | 13px (0.8125rem) | 600 | 1.3 | Form labels (above input, `--texto-suave`, matches `Login.css`), badges in `text-transform: uppercase; letter-spacing: 0.04em`, table header cells |
| Heading | 20px (1.25rem) | 600 | 1.2 | Page title (`<h1>`), modal titles, card/section titles. Band allowed by .planning/PROJECT.md §3 is 18–22px — this phase locks **20px** for all admin headings |

**Display row: not used in this phase** (serif display type is reserved for Login/Cardápio Público).

**Restricted 700 weight** — allowed ONLY on: (a) numeric saldo values in tables (esp. baixo estoque in `--erro`, .planning/PROJECT.md §5.2 "negrito"), (b) dashboard metric values. Badge text uses 600 (.planning/PROJECT.md §3 caps badges at 500–600); primary button labels use 600 (.planning/PROJECT.md §5.1 specifies no weight). Never on body paragraphs.

## Color

Tokens verbatim from `index.css` `:root` (values sampled from the school crest — .planning/PROJECT.md §2):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--fundo` `#F7FAF5` + `--branco` `#FFFFFF` | Page background (`--fundo`, already applied by Layout) with all content on white surfaces: cards, tables, modals, inputs |
| Secondary (30%) | `--verde-escuro` `#124C0F` + `--verde-tint` `#EDF4EA` | Sidebar (Layout, existing), primary buttons, page/modal headings, table header text; `--verde-tint` for table header background, row hover (at 50%), neutral tags |
| Accent (10%) | `--verde-vivo` `#48BB2C` + `--amarelo` `#C5D227` | **Restricted — explicit list below** |
| Destructive | `--erro` `#B3261E` (+ `--erro-fundo` `#FBEDEB`) | Destructive/danger actions and error states only: danger button border+text, `role="alert"` boxes, baixo-estoque saldo text, badge "Excluído" (text on `--erro-fundo`) |

**Accent reserved for (exhaustive list — nothing else):**

`--verde-vivo`:
1. Focus rings — `outline: 2px solid var(--verde-vivo)` (+ soft `box-shadow: 0 0 0 2px rgba(72,187,44,0.25)` on inputs, per `Login.css`)
2. Active sidebar indicator (already implemented in Layout)
3. 3px top-border accent on Dashboard metric cards (`border-top: 3px solid var(--verde-vivo)`, `CardapioPublico.css` pattern)
4. Large status badge "Recebido"/"Confirmado" — white text permitted **only** on these large badges (.planning/PROJECT.md §6 exception); never as background behind small text
5. Input/select focus border color

`--amarelo` (always with dark `--texto` text — mandatory contrast, .planning/PROJECT.md §6):
1. Status badges "Alterado"/"Pendente"
2. Border of the mandatory justification field **until filled** (.planning/PROJECT.md §5.4 — audit highlight)
3. Row highlight for XML-parsed items that need manual item selection

**Forbidden combinations (checker must flag):** white text on `--verde-vivo` at body/label sizes (~2.4:1); `--amarelo` with white or light text; full red (`--erro`) backgrounds — errors are `--erro` text on `--erro-fundo`; any blue/purple/orange; dark mode.

**Low-stock rule (F8, .planning/PROJECT.md §5.2):** when `saldo_atual < 5.0` (backend constant `LIMIAR_BAIXO_ESTOQUE`), the saldo cell renders `--erro` **bold (700)** text + a "Baixo estoque" badge (`--erro-fundo` bg, `--erro` text). Never a solid red row. Non-low rows show badge "OK" (`--verde-tint` bg, `--verde-escuro` text). Saldo always formatted `toFixed(2)`.

## Copywriting Contract

All UI copy is **PT-BR**, sentence case, no exclamation marks, no technical jargon (users: kitchen admin and secretary, non-technical). Backend `ApiError.detail` messages arrive PT-BR-ready — display them verbatim inside `role="alert"` boxes.

### Global defaults

| Element | Copy |
|---------|------|
| Primary CTA (global rule) | verb + noun, e.g. "Novo usuário", "Novo item", "Novo prato", "Nova entrega"; submit inside modals: "Salvar" (progress: "Salvando…") |
| Empty state heading | "Nenhum {recurso} cadastrado" (per-page variants below) |
| Empty state body | states value + next step, e.g. "Cadastre o primeiro item para começar o controle de estoque." |
| Error state (load failure) | "Não foi possível carregar os dados. Verifique se o backend está rodando e tente novamente." + inline "Tentar novamente" button |
| Error state (submit failure) | backend `detail` verbatim in `role="alert"` box (`--erro-fundo` bg, `--erro` text, 14px) |
| Error state (401 mid-session) | "Sua sessão expirou. Entre novamente." (ProtectedRoute redirects on next navigation) |
| Destructive confirmation (pattern) | modal: "Excluir {recurso} {nome}? Esta ação não pode ser desfeita." — buttons: "Cancelar" (secundário) + "Excluir" (perigo) |

### Per-page contract

**5.1 Dashboard (`/admin`)**
- Page title: "Dashboard". Subtitle (14px, `--texto-suave`): "Visão geral da merenda escolar".
- 4 metric cards (white, `--verde-vivo` 3px top border): "Itens no estoque" (total_itens), "Itens em baixo estoque" (baixo_estoque — number in `--erro` 700 when > 0), "Entregas nos últimos 7 dias", "Alunos hoje".
- Sections: "Refeições de hoje" (4 rows always; prato `null` → "Prato não definido" in `--texto-suave`; badges "Confirmado" verde-vivo / "Pendente" amarelo), "Itens críticos" (list; empty → "Nenhum item em baixo estoque."), "Entregas" (últimos 7/30 dias; `ultima_data` null → "Nenhuma entrega registrada ainda.").
- With a fresh database, zeros are a **valid populated state** (F6) — cards/sections always render.

**5.2 Usuários (`/admin/usuarios`)**
- Primary CTA: "Novo usuário". Modal titles: "Novo usuário" / "Editar usuário".
- Edit modal password label: "Nova senha (deixe em branco para manter a atual)".
- Perfil select options: "Admin", "Secretaria", "Cozinheira" (badge de perfil in table mirrors `Layout.css` pills: admin → `--verde-escuro`/branco; secretaria → `--verde-tint`/`--verde-escuro`; cozinheira → `--amarelo`/`--texto`).
- Empty: heading "Nenhum usuário cadastrado" / body "Crie usuários para controlar quem acessa o sistema."
- Destructive: "Excluir usuário {nome}? Esta ação não pode ser desfeita." (409 duplicate name → backend detail in `role="alert"`).

**5.3 Itens (`/admin/itens`)**
- Primary CTA: "Novo item". Columns: Nome, Unidade (KG/L), Saldo, Status, Ações.
- Status column: "Baixo estoque" badge (saldo < 5.0, must "gritar" — CONTEXT.md specifics) / "OK" badge otherwise.
- Row action "Conversões" opens modal "Conversões de {item}" (medida caseira + peso em kg; add/remove). Empty conversões: "Nenhuma conversão cadastrada. Sem conversão, o lançamento de refeições com medidas caseiras falha."
- Empty: "Nenhum item no estoque" / "Cadastre o primeiro item para começar o controle de estoque."
- Destructive: "Excluir o item {nome}? Esta ação não pode ser desfeita."

**5.4 Cardápio (`/admin/cardapio`)**
- Primary CTA: "Novo prato". Tipo select restricted to: "Lanche da Manhã", "Almoço", "Lanche da Tarde", "Janta" (exact backend strings).
- Row action: "Editar receita" → `/admin/receitas/:id`.
- Empty: "Nenhum prato cadastrado" / "Cadastre o primeiro prato para montar o planejamento semanal."
- Destructive: "Excluir o prato {nome}? Esta ação não pode ser desfeita."

**5.5 Receitas (`/admin/receitas/:id`)**
- Header: "Receita: {nome do prato}" + tipo badge + "Voltar ao cardápio" (secundário).
- Add form (inline above table): item select + quantidade (`step="0.1"`) + medida caseira + "Adicionar ingrediente" (primário).
- Rows: inline "Editar" (quantidade/medida) + "Remover" (perigo).
- Empty: "Este prato ainda não tem ingredientes" / "Adicione ingredientes com a quantidade por aluno em medida caseira (ex.: 1 xícara, 2 colheres)."
- Destructive: "Remover {item} da receita? Esta ação não pode ser desfeita."

**5.6 Planejamento (`/admin/planejamento`, admin + secretaria)**
- Page title: "Planejamento semanal". Week nav: "‹ Semana anterior" / date input (label "Semana de referência") / "Próxima semana ›"; caption shows "Semana de {segunda} a {domingo}" (14px, `--texto-suave`).
- Grid: rows = dias (Segunda…Domingo, backend index 0–6), columns = the 4 planning slots; cell = prato dropdown **filtered by the slot's mapped `tipo_refeicao`** (research gotcha #6) + "— A definir —" empty option.
- Empty cell rendering: "A definir" in `--texto-suave` italic.
- Primary CTA: "Salvar planejamento" (progress "Salvando…"); success feedback (transient inline text, `--verde-escuro`): "Planejamento salvo." Choosing "— A definir —" on a filled slot deletes the vigente entry on save.
- Error: backend detail verbatim (e.g., invalid day/type).

**5.7 Entregas (`/admin/entregas`, admin + secretaria)**
- Primary CTA: "Nova entrega" → choice modal: "Lançamento manual" / "Importar XML (NF-e)".
- List columns: Data/hora, Itens (qtd), Registrado por, Ações ("Ver detalhes" → detail modal "Entrega #{id}", items with badges + justificativas).
- Empty: "Nenhuma entrega registrada" / "Registre a primeira entrega manualmente ou importe o XML da nota fiscal."
- Editable table (both flows): columns Item (select), Quantidade, Ação, (remover). Action badges: "Recebido" (verde-vivo bg, white, large), "Alterado" (amarelo bg, `--texto`), "Excluído" (`--erro-fundo` bg, `--erro`) — exact backend strings `'recebido' | 'alterado' | 'excluído'` (com acento).
- **Justification modal (D-10, F11):** title "Justificativa obrigatória"; body (14px): "Alterar ou excluir um item da nota exige justificativa. Esse registro faz parte da prestação de contas do PNAE." Textarea label "Justificativa" with `--amarelo` border until filled; "Confirmar" disabled while empty. Triggered by: changing a parsed quantity (→ `alterado`) or removing a row (→ `excluído`; row stays visible, struck-through with "Excluído" badge — never silently vanishes).
- Submit CTA: "Confirmar recebimento" — **disabled with 0 rows** (backend 422 guard); success: backend `mensagem` verbatim + list refetch.
- XML errors: "Não foi possível ler o arquivo. Verifique se é um XML de NF-e válido." Unmatched item rows: highlighted with `--amarelo` border + helper "Item não reconhecido — selecione o item correspondente no estoque." NF header info shown: "NF nº {nNF} — {emitente}".

## Page Contracts (component inventory for planner/executor)

Each page = `src/pages/admin/{Nome}.tsx` + `{Nome}.css` (co-located, D-01), rendered inside `<ProtectedRoute perfis={…}><Layout>` (D-05). Shared class vocabulary to replicate per page CSS (token-driven, no new globals):

- `.pagina-header` — flex row: `<h1>` (Heading spec) + subtitle + primary CTA right-aligned; margin-bottom xl (32px)
- `.card` — white, 1px `--borda`, `--raio`, `--sombra-card`, padding 24px
- `.tabela-container` / `.tabela` — per .planning/PROJECT.md §5.2 + overflow rule above
- `.badge` + `-ok` / `-pendente` / `-excluido` / `-neutro` / `-perfil-admin` / `-perfil-secretaria` / `-perfil-cozinheira` variants per Color section
- `.btn-primario` / `.btn-secundario` / `.btn-perigo` — per .planning/PROJECT.md §5.1 (incl. `:focus-visible` outline verde-vivo, disabled state `--verde-tint`/`--texto-suave`)
- `.modal-overlay` / `.modal-content` / `.modal-header` / `.btn-fechar` — **structure** from `PainelCozinha.css:152-201`, **re-tokenized**: overlay `rgba(18, 76, 15, 0.35)`, content radius 12px, max-height 90vh scroll (never the legacy black overlay/hex colors)
- `.form-group` / `.form-input` — from `Login.css` (label 13px 600 `--texto-suave` above input; focus ring verde-vivo)
- `.alerta-erro` — `--erro-fundo` bg, `--erro` text, `--raio`, 14px, `role="alert"` (Login.css `.login-erro` pattern)
- `.campo-auditoria` — textarea with `border: 1px solid var(--amarelo)` until filled (.planning/PROJECT.md §5.4)

**Interaction rules:** all mutations via modal forms (criar/editar) or inline row edit (Receitas quantidade, Entregas linhas); every submit uses `fetchJson` + `try/catch (ApiError)`; success closes modal + refetches list (Receitas/Entregas refetch detail per research gotcha #11); no `alert()`, no optimistic deletes — confirm-then-act per Destructive inventory.
